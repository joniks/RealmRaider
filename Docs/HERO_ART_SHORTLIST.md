# Blood Knight Art Reboot — Licensed Hero Shortlist

Date: 2026-09-05
Pass: Diamond 07.0 — research and selection only

## Decision

**Visual recommendation: dark_igorek — The Forgotten Knight.** This is the first candidate that truly reaches the intended dark-fantasy hero quality: a distinctive rose-entwined crusader silhouette rather than generic armour. The creator-published Sketchfab entry explicitly identifies **CC Attribution / CC BY 4.0**, a Blender 4.3 rig and a downloadable source. At **223.7k triangles**, it is emphatically not ready for the Android build; it must be treated as a licensed hero source for a later retopology, material bake and LOD pass. It is still the best visual north star for Blood Knight.

**Technical recommendation: System G6 / Qoma — Modular RPG Characters.** It remains the best documented CC0 production option: two modular characters at roughly 2–3k triangles, 512–1024 px textures, rigging, and roughly 45 animations per character. It is the safe fallback if the visual candidate cannot meet mobile performance or Unity import requirements.

**Backup: crownjoshua — Knight (Rigged – Mid Poly).** This is the stronger candidate when the immediate priority is a more detailed armour silhouette rather than ready-made clips. Its visible armour/body split is likely to read well at the current camera distance, but it is supplied as a Rigify Blender file and has no published animation list; it needs an import/rig proof before approval.

**User action required:** choose the visual recommendation, the CC0 technical fallback, or the existing mid-poly backup before any download/import. All are zero-price public downloads according to their source pages, but the implementation pass must still download from the linked creator-published source, retain its licence text/provenance, inspect the actual files, and validate Unity import before replacing the hero. No model was downloaded or imported in this pass.

## Why other sources are not in the recommendation

- Current Quaternius Animated Knight remains a valid **CC0 technical fallback**, but its existing Unity import is Generic because Humanoid validation failed and its player-facing quality is the reason for this pass. It is not a replacement candidate.
- Paid store assets with standard marketplace EULAs are intentionally excluded: their source files are commonly licensed for use in an end product but not for unrestricted repository redistribution. This pass requires both commercial game use **and repository inclusion**.
- “Free” assets lacking a direct creator licence, personal-only licences, NC clauses, or unclear redistribution terms are excluded even if their screenshots look better.

## Exact visual-only integration path after approval

The chosen source replaces **only** the current visual prefab:

1. Retain `Assets/Game/Art/ThirdParty/Quaternius/AnimatedKnight/KnightCharacter.fbx` and the existing `Assets/Game/Resources/Characters/BloodKnightHero.prefab` until the new asset has passed import and smoke checks.
2. Add the approved source under a new, creator-named `Assets/Game/Art/ThirdParty/...` folder; keep the source licence text next to it and add one provenance entry to `Docs/THIRD_PARTY_ASSETS.md` in the later intake pass.
3. Create a replacement **visual-only** `Resources/Characters/BloodKnightHero` prefab. It must not contain gameplay colliders, a `CharacterController`, `Health`, controllers, camera, `AudioListener`, or an Animator Controller unless a separately authorised animation pass validates it.
4. Keep `PrototypeRuntimeFactory.BloodKnightRecipe.BaseBodyPrefab` pointing at that Resources prefab. `CharacterVisualAssembler` will instantiate it below `Character Visual Modules/Presentation Pivot` and disables all child colliders; it does not replace the root `CombatEntity` or its active controller.
5. Import validation must check actual mesh/material count, texture dimensions, Read/Write, no cameras/lights/colliders, Unity Humanoid avatar validity, and available clips. If the rig is Generic or clips are unusable, document that fact and retain presentation-only motion rather than changing gameplay.
6. Run the existing visual assembler, possession, feedback, Sylvan and Defender smoke tests. The fallback primitives and current Quaternius source remain available until the new prefab passes those checks.

This preserves the current `CharacterVisualRecipe` / `CharacterVisualAssembler` seam: the art swap remains a child-presentation replacement and never changes combat data, possession identity, root physics, movement, camera target, controls, or balance.
